\begin{abstract}
	The Design Structure Matrix (DSM) is a compact representation of task dependencies in large-scale engineering and software systems. Efficient reordering of DSM tasks to minimize feed-back dependencies is a computationally challenging problem with significant practical importance. In this report, we present an implementation of two classical strongly connected component (SCC) algorithms --- Tarjan's algorithm and the Sharir-Kosaraju algorithm --- using the Compressed Sparse Column (CSC) data structure in order to decompose DSMs into block lower triangular form. We evaluate both algorithms on a suite of benchmark sparse matrices and compare their performance in terms of running time, number of SCCs identified, and solution quality as measured by the number of feed-back marks and total feed-back distance. \section{Introduction}\label{sec:intro}

Modern software systems and engineering projects are constantly growing in complexity, often comprising hundreds or even thousands of interdependent tasks that require the collaboration of many participants from diverse backgrounds. Traditional management tools such as Gantt charts and Critical Path Method (CPM) networks are well-suited for modeling sequential and parallel task executions. However, they fail for interdependent tasks, i.e.,~when the output of one task is needed as input for another task, and vice versa. As these tasks are especially common in complex product development (PD), project managers require tools capable of modeling interdepdencies and identifying a task ordering that minimizes potential conflicts in information flow~\cite{Yassine2001AnIT}.

An effective tool for representing the pairwise information flow between a set of tasks is a square matrix called the \textit{design structure matrix} or \textit{dependency structure matrix} (DSM)~\cite{hossain_projectdescription}. If a project is composed of $n$ tasks, a DSM models the information flow between these tasks in a binary $n \times n$ matrix, where the rows and columns are both labeled by the same ordered list of tasks. Marks in the DSM indicate the relationship between two tasks. The marks in a single row of the DSM show all the tasks that provide input that is needed to perform the task in the corresponding row. Similarly, marks in a single column display all the tasks that receive information from the corresponding task in that column~\cite{Yassine2001AnIT}. For instance, the $(i,j)$-th entry of the DSM is $1$, if task $i$ depends on task $j$, and it is $0$ if task $i$ can be completed independent of task $j$. Furthermore, the diagonal entries do not represent dependencies with other tasks and are therefore often disregarded. Equivalent to its matrix representation, a DSM can also be displayed as a directed graph~\cite{eppinger2012}.

If the ordering of tasks along the axes is interpreted as the sequence in which the tasks are executed, then three different types of dependencies can be identified for a pair of tasks~\cite{Yassine2001AnIT}.

\begin{itemize}
	\item \textbf{Feed-Forward}: Marks that represent the forward transfer of information. Task $j$ supplies information for task $i$ and is scheduled before it, i.e.,~$j < i$. The pair $(i,j)$ is located below the diagonal. These dependencies are easy to solve as task $i$ just waits for task $j$ to finish.
	\item \textbf{Feed-Back}: Marks that represent the backward transfer of information. Task $j$ supplies information for task $i$ but is scheduled afterwards, i.e.,~$i < j$. The pair $(i, j)$ is located above the diagonal. This means that the required inputs (task $j$) are not available at the time of executing task $i$, making it necessary to make assumptions about the inputs that may not hold if task $j$ is finally executed. In the worst case, the dependent task $i$ needs to be re-executed.
	\item \textbf{Coupled}: Task $i$ and $j$ are mutually dependent and both require input from each other, i.e.,~the pairs $(i, j)$ and $(j,i)$ both exist in the DSM. These tasks require iteration as neither task can be started first without making assumptions about the output of the other task.
\end{itemize}

An important objective from a project manager's perspective is reorder the tasks to reduce the number of feed-back marks to minimize the potential conflicts that could arise during the execution stage. This process is regarded as \textit{partitioning}~\cite{steward1981,Yassine01091999}.

In the ideal scenario, the permutation of the rows and columns leads to a lower triangular form in the DSM, i.e.,~all feed-back marks get eliminated. However, not all DSMs can be permuted to lower triangular form~\cite{Yassine2001AnIT,hossain_addendum}. Especially for complex engineering systems it is highly unlikely that all feed-back marks can be moved underneath the diagonal. If the underlying directed graph describing the DSM contains at least one cycle, the best achievable result is the \textit{block lower triangular form} (BLTF), in which all vertices participating in cycles are gathered into diagonal blocks~\cite{hossain_addendum}. Furthermore, the second objective is to minimize the total distance of the remaining feed-back marks from the diagonal, as smaller and more tightly packed diagonal blocks cause fewer tasks to be involved in each iteration cycle, leading to a faster development process~\cite{eppinger2012}.

With these two objectives at hand, the DSM partitioning problem can be stated as follows. Let $A \in \{0, 1\}^{n \times n}$ be a binary matrix representing the DSM and let $P \in \{0, 1\}^{n \times n}$ be a permutation matrix obtained by permuting the columns/ rows of the identity matrix $I_n$. The symmetrically permuted matrix $A' = P^\top A P$ represents the reordered DSM, where the goal is to find the permutation matrix $P$ that minimizes two quantities~\cite{hossain_addendum}:

\begin{enumerate}
	\item The number of feed-back marks $|\text{FBM}|$, where
	      \begin{equation*}
		      \text{FBM} = \{ a'_{ij} \neq 0 \mid j > i, \; i,j = 1, 2, \ldots, n \}
	      \end{equation*}

	\item The total feed-back distance TFBD of feed-back marks from the diagonal
	      \begin{equation*}
		      \text{TFBD} = \sum_{a'_{ij} \in \text{FBM}} (j - i),
	      \end{equation*}
\end{enumerate}

Over the years, several algorithmic approaches have been proposed in the literature to solve the DSM partitioning problem~\cite{Yassine2001AnIT,eppinger2012}. However, most methods share the same structure and only differ in the way they identify \textit{information cycles}, i.e.~cycles of two or more mutually dependent tasks. Usually, the partitioning starts by moving tasks with no incoming dependencies (empty rows) to the top of the DSM, and moving tasks with no outgoing dependencies to the bottom of the DSM. Once the these tasks are rearranged, they are removed from the DSM with all their corresponding marks. These steps are repeated until no further reordering is possible~\cite{Yassine2001AnIT}. Any remaining task in the DSM must then be part of at least one information cycle, which must be identified explicitly. Three classical methods have been proposed for this~\cite{eppinger2012,Yassine01091999}:

\begin{itemize}
	\item \textbf{Path Searching}: Every remaining activity has an off-diagonal mark~\cite{eppinger2012}. An activity is arbitrarily chosen and a list of successors is generated by tracing the information flow until a task in encountered twice~\cite{sargentwesterberg1964,steward1981}. All tasks between the first and second occurrence constitute an information cycle and are grouped together~\cite{Yassine2001AnIT}. The approach can also be applied recursively to reveal sub-cycles~\cite{eppinger2012}.
	\item \textbf{Powers of the Adjacency Matrix}: The binary DSM is raised to the $n$-th power. A non-zero diagonal entry indicates that the corresponding task can reach itself in $n$ steps, which confirms a cycle~\cite{Yassine2001AnIT,warfield1973}. However, finding blocks of coupled activities through this method is computationally expensive, especially for large matrices~\cite{eppinger2012}.
	\item \textbf{Depth-First Search}: The most efficient way to identify subsets of coupled activities is Tarjan's depth-first search algorithm~\cite{eppinger2012,TARJANalgo}. Following the outputs of each task detects dependency paths that cycle back to the same task.
\end{itemize}

When all information cycles are identified, the involved tasks are grouped together to be treated as a single representative block~\cite{Yassine2001AnIT}. Then the procedure restarts on the remaining tasks, which ultimately yields the block lower triangular form of the DSM.

The remainder of this report is structured as follows: Section~\ref{sec:solution} describes CSC matrix data structure and the algorithms that were used to permute the DSM, including their asymptotic runtime and space complexities. Section~\ref{sec:results} presents the results of our numerical experiments on benchmark matrices in terms of solution quality and running time. Section~\ref{sec:conclusion} summarizes our findings and provides future research directions of this work.


\section{Description of Solution}\label{sec:solution}

Not every DSM can be permuted to strict lower triangular form; when the underlying graph contains cycles, the best achievable result is the block lower triangular form (BLTF)~\cite{hossain_addendum}. We compute a BLTF of the input DSM in six stages: CSC storage, SCC decomposition, topological block ordering, tearing, banding, and permutation application.

\subsection{Compressed Sparse Column Representation}

Since DSMs are sparse ($\mathtt{nnz} \ll n^2$), we store the matrix in compressed sparse column (CSC) format~\cite{barrett1994templates,hossain_addendum} using a column pointer array $\texttt{col\_ptr}[0 \ldots n]$ and a row array $\texttt{row\_ind}[0 \ldots \mathtt{nnz}{-}1]$. The nonzero row indices of column~$j$ occupy $\texttt{row\_ind}[\texttt{col\_ptr}[j] \ldots \texttt{col\_ptr}[j{+}1){-}1]$. Since DSMs are binary, no value array is needed. Reading the DSM as a directed graph $G(A)$, column~$j$ lists the out-neighbours of vertex~$j$, so iterating them costs $O(\deg^+(j))$---the access pattern required by DFS. Total storage is $O(n + \mathtt{nnz})$. The transposed graph needed by Kosaraju-Sharir is also computed in $O(n + \mathtt{nnz})$ time.

\subsection{Strongly Connected Component Decomposition}\label{sec:scc}

Each SCC in the directed graph of the DSM corresponds to a maximal set of mutually dependent tasks that cannot be decoupled by reordering alone. We implement two SCC algorithms, Tarjan's and Kosaraju-Sharir---which share an iterative DFS over the CSC structure, using a stack instead of recursion. Following Erickson's DFS framework with \textsc{PreVisit} and \textsc{PostVisit} hooks~\cite{erickson2019algorithms}, our implementation adds \textsc{PreEdge} and \textsc{PostEdge} callbacks to handle edge-level events.

\paragraph{Tarjan's Algorithm.}
Tarjan's algorithm~\cite{TARJANalgo} finds all SCCs in a single DFS pass. Each vertex~$v$ gets a starting time $v.\mathit{pre}$ and a value $\mathit{low}(v)$: the smallest starting time reachable from~$v$ by tree edges followed by at most one non-tree edge~\cite{erickson2019algorithms}. On first visit, $v$ is pushed onto a stack~$S$. When an edge $v \!\to\! w$ leads to a vertex still on~$S$, we set $\mathit{low}(v) \leftarrow \min\{\mathit{low}(v),\, w.\mathit{pre}\}$. After returning from a child~$w$, we propagate $\mathit{low}(v) \leftarrow \min\{\mathit{low}(v),\, \mathit{low}(w)\}$. When a vertex finishes with $\mathit{low}(v) = v.\mathit{pre}$, it is the root of a sink component~\cite{erickson2019algorithms}: all vertices above it on~$S$ are popped to form the SCC. Each vertex is pushed and popped exactly once, so the algorithm runs in $O(V + E)$ time and $O(V)$ auxiliary space~\cite{erickson2019algorithms,TARJANalgo}. Pseudocode is given in Erickson~\cite{erickson2019algorithms} (Figure~6.19).

\paragraph{Kosaraju-Sharir Algorithm.}
The Kosaraju-Sharir algorithm~\cite{SHARIRalgo} uses two DFS passes. Phase~1 runs DFS on the original graph, pushing each vertex onto a stack at finish time. Phase~2 builds $\mathit{rev}(G)$ and runs DFS in reverse postorder; each tree yields exactly one SCC~\cite{erickson2019algorithms}. Both passes give $O(V + E)$ time and $O(V + E)$ space~\cite{erickson2019algorithms,SHARIRalgo}. Pseudocode is in Erickson~\cite{erickson2019algorithms} (Figure~6.16).

\subsection{Block Ordering}

The condensation $\mathit{scc}(G)$ contracts each SCC to a single vertex~\cite{erickson2019algorithms} and is stored as a new CSC matrix. Since it is always a DAG, we topologically sort it with Kahn's algorithm~\cite{kahn1962topological} to determine the block order. Both steps run in $O(k + m')$ time, where $k$ is the number of SCCs and $m'$ the number of inter-component edges~\cite{kahn1962topological}.

\subsection{Tearing}\label{sec:tearing}

Tearing selects feed-back marks whose removal yields a lower triangular block~\cite{Yassine2001AnIT}. We approximate the minimum feedback arc set within each non-trivial SCC using Algorithm~GR of Eades et~al.~\cite{eades1993fast} (Algorithm~\ref{alg:gr}). For each SCC with $k$ vertices, the local subgraph is extracted into successor/predecessor lists with in-degree ($d^-$) and out-degree ($d^+$) arrays.

\begin{algorithm}[H]
	\caption{Algorithm GR~\cite{eades1993fast}}\label{alg:gr}
	\begin{algorithmic}[1]
		\State $s_1 \gets [\,],\quad s_2 \gets [\,]$
		\While{$G \neq \emptyset$}
		\While{$G$ has a sink}
		\State choose a sink $u$; remove $u$ from $G$; $s_2 \gets u \cdot s_2$
		\EndWhile
		\While{$G$ has a source}
		\State choose a source $u$; remove $u$ from $G$; $s_1 \gets s_1 \cdot u$
		\EndWhile
		\If{$G \neq \emptyset$}
		\State choose $u$ with maximum $\delta(u) = d^+(u) - d^-(u)$
		\State remove $u$ from $G$; $s_1 \gets s_1 \cdot u$
		\EndIf
		\EndWhile
		\State \Return $s_1 \cdot s_2$
	\end{algorithmic}
\end{algorithm}

\noindent Edges that go backward in the returned ordering are the feedback arcs. Algorithm~GR runs in $O(m)$ time when the max-$\delta$ selection at line~10 uses a bucket structure~\cite{eades1993fast}; our implementation uses a linear scan instead, giving $O(k^2 + m)$ time and $O(k + m)$ space per SCC. Singleton SCCs are returned unchanged.

\subsection{Banding}

Banding reorders tasks within each non-trivial SCC ($|C| > 2$) to push feed-back marks closer to the diagonal, minimizing TFBD~\cite{hossain_addendum}.

\paragraph{Reverse Cuthill-McKee Ordering.}
The RCM algorithm was originally designed to reduce the bandwidth of symmetric sparse matrices~\cite{cuthill1969reducing}. Applied to an SCC subgraph, it concentrates nonzeros near the diagonal, which directly reduces TFBD. A pseudoperipheral starting vertex is selected via the George-Liu algorithm~\cite{georgeliu1979}, which runs successive BFS rounds. From this vertex, a Cuthill-McKee BFS~\cite{cuthill1969reducing} visits neighbours in ascending degree order; the result is then reversed to yield the RCM ordering~\cite{george1971computer}.

\paragraph{Adjacent-Swap Refinement.}
Both the torn and RCM orderings are refined by a greedy adjacent-swap heuristic (Algorithm~\ref{alg:swaprefine}). Each pass scans adjacent pairs and accepts a swap only if it strictly decreases TFBD without increasing FBM. The procedure halts when no improvement is found or after 20 passes.

\begin{algorithm}[H]
	\caption{Adjacent-Swap Refinement}\label{alg:swaprefine}
	\begin{algorithmic}[1]
		\Require ordering $\sigma = [\sigma_0, \ldots, \sigma_{k-1}]$, directed edge set $E$, max passes $P$
		\Ensure refined ordering $\sigma$
		\State $\mathit{pos}[\sigma_i] \gets i$ for all $i$ \Comment{inverse permutation}
		\State $\mathit{inc}[v] \gets \{e \in E \mid v \in e\}$ for all $v$ \Comment{incidence lists}
		\For{$\mathit{pass} = 1, \ldots, P$}
		\State $\mathit{improved} \gets \textbf{false}$
		\For{$i = 0, \ldots, k - 2$}
		\State $a \gets \sigma_i,\quad b \gets \sigma_{i+1}$
		\State $\Delta\text{FBM} \gets 0,\quad \Delta\text{TFBD} \gets 0$
		\For{each edge $(s, d) \in \mathit{inc}[a] \cup \mathit{inc}[b]$}
		\State compute old and new positions of $s, d$ under the swap $a \leftrightarrow b$
		\State update $\Delta\text{FBM}$ and $\Delta\text{TFBD}$ from old vs.\ new contribution
		\EndFor
		\If{$\Delta\text{TFBD} < 0$ \textbf{and} $\Delta\text{FBM} \leq 0$}
		\State swap $\sigma_i \leftrightarrow \sigma_{i+1}$; update $\mathit{pos}$
		\State $\mathit{improved} \gets \textbf{true}$
		\EndIf
		\EndFor
		\If{$\lnot\, \mathit{improved}$} \textbf{break} \EndIf
		\EndFor
		\State \Return $\sigma$
	\end{algorithmic}
\end{algorithm}

\noindent The refined ordering with fewer feed-back marks is kept; ties are broken by lower TFBD. If the unrefined RCM ordering increased FBM, it is discarded. Algorithm~\ref{alg:banding} summarizes the full procedure.

\begin{algorithm}[H]
	\caption{Banding an SCC}\label{alg:banding}
	\begin{algorithmic}[1]
		\Require SCC vertices $C$ with $|C| = k > 2$, DSM matrix $A$
		\Ensure banded ordering of $C$
		\State build local subgraph $G$ from $A$ restricted to $C$
		\State $\sigma_{\text{torn}} \gets$ identity ordering (from tearing)
		\State $\hat{\sigma}_{\text{torn}} \gets \Call{SwapRefine}{\sigma_{\text{torn}}, E(G), 20}$ \Comment{Algorithm~\ref{alg:swaprefine}}
		\State find pseudoperipheral vertex $r$ in $G$ \Comment{George-Liu~\cite{georgeliu1979}}
		\State $\sigma_{\text{rcm}} \gets \Call{RCM}{G, r}$ \Comment{Cuthill-McKee~\cite{cuthill1969reducing}, reversed~\cite{george1971computer}}
		\If{$\text{FBM}(\sigma_{\text{rcm}}) \leq \text{FBM}(\sigma_{\text{torn}})$}
		\State $\hat{\sigma}_{\text{rcm}} \gets \Call{SwapRefine}{\sigma_{\text{rcm}}, E(G), 20}$
		\If{$\hat{\sigma}_{\text{rcm}}$ has fewer FBM, or equal FBM and lower TFBD}
		\State \Return $\hat{\sigma}_{\text{rcm}}$
		\EndIf
		\EndIf
		\State \Return $\hat{\sigma}_{\text{torn}}$
	\end{algorithmic}
\end{algorithm}

\noindent RCM runs in $O(k + m)$ time~\cite{cuthill1969reducing,george1971computer}. Each refinement pass costs $O(k \cdot \bar{d})$ where $\bar{d}$ is the average degree; with at most 20 passes, overall banding requires $O(k + m)$ time and space per SCC.

\subsection{Permutation Application}

The banded per-block orderings are concatenated in topological order to form a global permutation $\pi$ in $O(n)$ time. The symmetric permutation $A' = P^\top A P$ is applied in CSC format by computing $\pi^{-1}$ in $O(n)$ time, then remapping each edge $(i,j)$ to $(\pi^{-1}(i),\, \pi^{-1}(j))$ in $O(n + \mathtt{nnz})$ time. Row indices within each column are then sorted; if column~$j$ has $d_j$ entries, this step costs $O(\sum_j d_j \log d_j) \leq O(\mathtt{nnz}\log n)$ since $d_j \leq n$. The total is $O(n + \mathtt{nnz}\log n)$ time and $O(n + \mathtt{nnz})$ space. The feed-back mark count and total feed-back distance are computed on both the original and permuted DSMs in $O(\mathtt{nnz})$ time.

\section{Numerical Results}\label{sec:results}

This section evaluates the proposed DSM reordering method on the benchmark matrices included in the project repository. In particular, we measure both \emph{solution quality} and \emph{computational cost} across the stages introduced in Section~\ref{sec:solution}: (i) SCC decomposition and topological block ordering (\texttt{TopoOnly}), (ii) intra-block tearing, and (iii) intra-block banding refinement. The final reordered DSM is obtained through the symmetric permutation $A' = P^\top A P$, and all metrics are computed on $A'$.

\subsection{Experimental Setup}

All experiments were executed with the benchmark mode of our implementation (\texttt{./out/main --bench}) using the same software and hardware environment for all matrices. The runs reported in this section were produced on an Apple M2 system with 8~GB RAM, compiled with Apple LLVM 17 under optimization flags (\texttt{-O3}, \texttt{-std=c++17}). For each timed algorithm, we use 2 warm-up runs and 5 timed runs, and report the mean, standard deviation, minimum, median, and maximum runtime in microseconds.

The benchmark suite contains 11 sparse matrices with dimensions ranging from $n=4$ to $n=27{,}770$ and nonzero counts from $4$ to $352{,}807$. This span allows us to examine both small example instances and large, complex graphs that represent realistic dependency systems. In addition to timing, we export matrix-level quality statistics and stage-wise optimization metrics to \texttt{out/optimization\_metrics.csv}, from which the plots in Figures~\ref{fig:fbm-stage}--\ref{fig:stage-avg} are generated.

\subsection{Stage-wise Optimization Quality}

The first observation is that the optimization stages consistently reduce feed-back structure in most matrices, often by a large margin. Averaged across the complete benchmark suite, the final banded ordering reduces the number of feed-back marks by \textbf{76.50\%} and the total feed-back distance by \textbf{85.95\%} relative to the baseline ordering. These reductions show that the proposed sequence is effective not only at reducing the count of above-diagonal dependencies, but also at moving the remaining ones much closer to the diagonal.

\subsection{Algorithmic Runtime Comparison}

Runtime behavior is evaluated with the benchmark table and scaling plots generated from \texttt{out/benchmark.csv}. The measured results indicate that both SCC implementations are efficient at all tested scales, with Tarjan consistently faster than Sharir-Kosaraju on average in our experiments. Across the full benchmark set, mean runtime is approximately 560.76~$\mu$s for Tarjan and 992.26~$\mu$s for Kosaraju, i.e., a ratio of about 1.77$\times$ in favor of Tarjan.

\begin{figure}[H]
    \centering
    \includegraphics[width=0.92\linewidth]{../out/plots/scaling.png}
    \caption{Log-log runtime scaling versus problem size $(V+E)$ for benchmarked algorithms.}
    \label{fig:scaling}
\end{figure}

The scaling trends in Figure~\ref{fig:scaling} are compatible with the expected near-linear behavior for graph-traversal steps over sparse structures. As anticipated, stages with heavier local refinement logic (especially banding) incur higher absolute runtime than pure traversal-based stages, but this additional cost is justified by the quality gains shown earlier. In practical terms, the optimization trade-off is favorable: banding is computationally heavier, yet it delivers the final quality improvements needed for cleaner diagonal concentration and clearer block structure in the reordered DSM.

\begin{figure}[H]
    \centering
    \includegraphics[width=0.78\linewidth]{../out/plots/optimization_stage_average.png}
    \caption{Average FBM and TFBD reduction by stage over all benchmark matrices.}
    \label{fig:stage-avg}
\end{figure}

Finally, Figure~\ref{fig:stage-avg} summarizes the global pattern: topological block ordering provides strong early improvements, tearing drives the main FBM reduction within SCCs, and banding supplies consistent final polishing, particularly in TFBD compactness. Therefore, the empirical evidence supports using the full multi-stage method instead of any single-stage reordering strategy when the objective is robust quality improvement across different DSM instances.
